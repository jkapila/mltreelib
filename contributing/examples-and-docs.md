# Writing documentation and examples

## Where things go

| Type | Reader's goal | Location |
|---|---|---|
| **Concept** | why and how it works (mechanism, math) | `docs/concepts/` |
| **Guide** | do a task end to end on real data | `docs/guides/` |
| **Example** | a short runnable script that teaches one topic | `examples/` (listed in `docs/examples.md`, generated by `scripts/docs/gen_examples_gallery.py`) |
| **Benchmark** | evidence, with a reproduce command | `docs/benchmarks/`, scripts in `benchmarks/`, manifest in `benchmarks/benchmarks.yaml` |
| **Blog** | a business case | `docs/blog/` |
| **Reference** | every parameter and method | `docs/reference/`, API pages generated by `scripts/docs/gen_api_doc.py` |

Update the page that already teaches the topic. Add a page only when none fits, and add it to the nav in `zensical.toml` (a page outside the nav fails `check_nav.py`).

## Structure of a guide or concept page

- Numbered steps (`## 1.`, `## 2.`) in the order a reader needs them. Each step except the last ends with one `**Next:**` line saying what the next step does and why it needs what this step produced. Closing sections (limits, references, related) stay unnumbered at the end.
- Say what the page is for in the first paragraph, and what it does not cover.

## Snippets and output

- Code is runnable. Mark it with `<!-- run -->` above the fence; `uv run python scripts/docs/run_snippets.py` runs the blocks of a page in order in one session and writes the real output into the output block that follows. Never type output by hand. `--check` fails when an output is stale.
- Use real datasets through `load_dataset` or `dataset_path` (fetched on demand, never bundled), or seeded synthetic data when the point is a known truth. No repo-relative paths, no untracked files.
- Snippets use the umbrella API, the data helpers (splits, accessors) instead of hand-rolled index arithmetic and list comprehensions, and no timing prints.
- Prose and tables quote only numbers that the output shows. When prose and output disagree, fix the prose.
- Figures are produced by a script named on the page and regenerated when the numbers change.

## Examples directory

- `examples/quickstart.py` and `examples/guides/<topic>.py`: short, finish in seconds to a minute, print what to look for, start with a docstring whose first line says what the script shows (it becomes the gallery description).
- Scripts that need packages beyond the dev environment (for example scikit-learn, LightGBM, optuna, scipy, pygraphviz) say so in a `Usage:` block of the docstring with `uv run --with <package> python <script>`, and the gallery's Run column shows that command. Never add such packages to the project's dependencies; optional ones (a figure renderer) are noted as optional.
- Slow runs and measurements belong in `benchmarks/`, tooling in `scripts/`.

## Building the docs

The docs build renders tree graphs, so it needs system Graphviz and the `docs` dependency group:

```sh
sudo apt-get install graphviz libgraphviz-dev      # or your platform's Graphviz development package
uv sync --group dev --group docs
```

The docs workflow does the same. The test workflow does not need Graphviz.

## Gates

```sh
uv run python scripts/docs/run_snippets.py --check
uv run python scripts/docs/check_nav.py
uv run python scripts/docs/check_benchmarks.py
uv run zensical build
uv run python scripts/docs/gen_examples_gallery.py      # after adding or editing an example
uv run python scripts/generate_sitemap_and_aeo.py       # sitemap and llms files
```

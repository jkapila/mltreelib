Generic optimizer and real-data tuning¶

mltreelib.solvers.optimize minimizes a callable scalar objective inside bounds. It is the public entry point for the shared optimization seam in the Rust core. One objective, bounds, budget, request, and result contract backs every method, so the result never changes shape when the method changes.

The library never substitutes another algorithm silently. Unknown methods raise ValueError. Incompatible problems return an unsupported result.

Python surface¶

from mltreelib.solvers import optimize

def objective(point):
    return (point[0] - 0.3) ** 2 + (point[1] + 1.5) ** 2

result = optimize(
    objective,
    [(-2.0, 2.0), (-2.0, 2.0)],
    method="random_search",
    samples=500,
    max_evaluations=500,
    seed=42,
)
Argument Meaning
objective Callable that takes one list of parameter values and returns one finite scalar.
bounds One (lower, upper) pair per parameter.
method Canonical method name.
start Starting point. Warm-starts the search.
max_evaluations Cap on objective calls.
max_iterations Cap on solver iterations.
tol Convergence tolerance used by the evolutionary methods. Other methods use their Rust method defaults.
seed Seed for stochastic methods.
gradient Optional callable returning one derivative per parameter.
samples Candidate count for the sampling methods.
initial_population Optional first candidates for population methods.
constraints COBYLA callback returning a fixed-length sequence of finite residuals.
constraint_kind Defaults to "inequality". COBYLA rejects "equality".
local_method Basin hopping's inner solver. Defaults to "lbfgs_b".

The result reports:

Field Meaning
best_x Best evaluated point, or an empty list when the method rejects the problem.
best_value Objective value at best_x, or NaN when no objective value is available.
iterations Solver iterations performed.
evaluations User objective evaluations performed.
status Termination status.
converged True only for converged and tolerance.
history Optional convergence history.
max_constraint_violation Largest constraint violation at best_x.
message Failure detail when the run did not succeed.

The API reference page Solvers & optimization holds the exact signatures and docstrings. Rust callers use the same contracts from mltreelib_core::generic; the Rust generic seam page lists every type, trait, and function with its doc comment.

Statuses¶

Status Meaning
converged The method reached its convergence test.
tolerance The tolerance test ended the run.
iteration_limit The iteration budget ended the run.
evaluation_limit The evaluation budget ended the run.
invalid_objective The objective returned a NaN or infinite value.
numerical_failure The numerical kernel failed.
infeasible No feasible point was found.
unsupported The method cannot solve the requested problem.
hard_error An unrecoverable error ended the run.

Budget exhaustion never reports success. A failed run never returns a converged status.

The optimizers¶

Random Search¶

Samples uniformly inside the bounds and keeps the best candidate. It needs no gradient, so it runs against any objective. It is the baseline every other method must beat under an equal evaluation budget.

Latin hypercube¶

Stratifies every dimension independently into samples strata, draws one point per stratum, and shuffles the strata with the seeded generator. The marginal coverage of each dimension beats uniform sampling at the same budget, which makes it the better initializer for population methods.

L-BFGS-B¶

The bounded smooth local solver. Each iteration computes the generalized Cauchy point along the piecewise-linear projected-gradient path, approximately minimizes the quadratic model over the free variables, runs a line search, projects onto the bounds, and tests the projected gradient norm over the free variables only. It keeps the limited-memory curvature update, so large parameter vectors stay practical. Without binding bounds its result matches the existing solve_lbfgs path.

BFGS¶

Full-memory BFGS with a dense inverse-Hessian approximation. Memory grows quadratically with the parameter count, so it suits small problems. It solves the same unconstrained objective as L-BFGS, which makes the two directly comparable. It rejects finite bounds instead of clipping them.

Nonlinear conjugate gradient¶

Polak-Ribiere direction with a documented restart rule. It needs only the objective and the gradient, keeps memory linear in the parameter count, and carries no curvature history. A negative Polak-Ribiere coefficient restarts the search direction.

Nelder-Mead¶

Derivative-free simplex search. It replaces the worst vertex each iteration with reflection, expansion, contraction, or shrink. The initial simplex shape and the two tolerances are configurable in Rust. It clips simplex vertices to the box.

Powell¶

Derivative-free conjugate-direction search. It performs sequential one-dimensional minimizations along a maintained direction set, and every line-search evaluation stays inside the box.

Simulated annealing¶

Global trajectory search over a bounded domain. The proposal is a per dimension bounded random displacement, the cooling schedule is geometric by default, and the boundary policy is either resampling or reflection. Clipping is not offered because it piles proposal mass on bound-active points. The best incumbent is tracked separately from the current point, so the result never degrades. The method ships as a heuristic with no optimality claim.

COBYLA¶

This derivative-free variant fits linear models over nearby evaluated points. It uses a box-shaped trust region and cyclic projection in place of Powell's original model subproblem solver. It keeps all evaluations inside the bounds. An infeasible result means the search found no feasible point. It does not prove that no feasible point exists.

result = optimize(
    lambda x: (x[0] - 2.0) ** 2 + x[1] ** 2,
    [(-5.0, 5.0)] * 2,
    method="cobyla",
    start=[1.5, 0.0],
    constraints=lambda x: [1.0 - x[0] ** 2 - x[1] ** 2],
    max_evaluations=200,
)

Basin hopping¶

A composition, not a numerical kernel. It perturbs the incumbent, runs an inner local solve through the same seam, and accepts the result with a constant-temperature Metropolis test. The step size is either fixed or adapted toward a target acceptance rate. Inner solve evaluations count against the outer budget, and a failed inner solve never erases the incumbent. Pass local_method to select lbfgs_b, bfgs, nonlinear_cg, nelder_mead, or powell. Use unbounded limits when the inner method is BFGS or nonlinear CG.

Evolutionary methods¶

The generic entry point and standalone GLM fits share the same population kernels. Generic optimization clips candidates to the supplied bounds. If you pass initial_population, the adapter evaluates those candidates against the same budget and starts the kernel from the best candidate. It reports the best evaluated point even if the budget ends partway through a generation.

Use unbounded limits for bfgs and nonlinear_cg. Only cobyla accepts a nonlinear constraint callback.

Budgets and determinism¶

max_evaluations caps the number of objective calls and max_iterations caps the number of solver iterations. Both limits report their own status. Every stochastic method takes an explicit seed, and the same inputs, bounds, options, and seed produce the same result. An omitted seed uses the fixed default seed, so omitted seeds stay reproducible.

Constraint semantics¶

An inequality residual is nonnegative at a feasible point. COBYLA accepts residuals down to -1e-8 by default and reports the largest raw violation at the returned point. The Rust CobylaOptions can change the tolerance. COBYLA rejects equalities before it evaluates the objective.

Leaf solver decoupling¶

Leaf building and solver selection are independent axes. A leaf declares the optimization problem it poses. A solver declares what it can solve. One compatibility lookup resolves a leaf, a response family, and a solver into a supported pairing or one precise rejection reason.

Solver Gradients Derivative-free L1 Monotone Box bounds Equality Nonlinear inequality Memory
irls yes no yes yes no no no quadratic
lbfgs yes no no no no no no linear
ccd no yes yes yes no no no linear
cmaes, shade, nes, ga no yes yes yes (GLM fits) yes (optimize) no no population

Rejected pairings name the missing capability, for example solver Lbfgs does not support L1 penalties.

Every fitted leaf persists two diagnostics: solver_used names the solver that ran, or that it did not apply, and leaf_problem_type names the objective the fit minimized. A closed-form leaf such as the weighted mean accepts any solver selection and reports the solver as not applicable instead of failing the fit.

Datasets¶

The benchmark Parquet files under datasets/ are not tracked in git. Fetch the suite once per checkout:

uv run python scripts/fetch_datasets.py
uv run python scripts/fetch_datasets.py --only diabetes airfoil_self_noise

One dataset can also arrive on demand through the loader, which caches it under ~/.cache/mltreelib/datasets/:

from mltreelib.datasets import load_dataset

data = load_dataset("airfoil_self_noise")

datasets/MANIFEST.md lists every dataset with its OpenML identifier, task, target, size, and license.

Tuning on real data¶

examples/optimize_generic.py tunes ModelTree hyperparameters on a local benchmark dataset and reports the holdout RMSE against a default tree. Both methods receive the same evaluation budget.

uv run python examples/optimize_generic.py --dataset airfoil_self_noise --budget 30

The real-data tests in tests/test_optimize.py check both sampling methods against the closed-form least-squares optimum. They skip if the dataset is not available locally.

Canonical benchmark¶

uv run python examples/benchmark_optimizers.py --budget 200 --offline --output-dir /tmp/mltreelib-optimizers

The runner writes JSON records and a Markdown summary. It covers analytic regression, synthetic landscapes, constrained problems, a binomial likelihood, tree tuning on Airfoil, and a split-threshold search. It records the domain because BFGS and nonlinear conjugate gradient require unbounded problems. It reports no objective gap for infeasible results or problems with no known optimum.
